# animation-pipeline — working notes for Claude sessions

Aaron's production pipeline for deliberately crude hand-drawn animated
shorts (9:16 reels). He writes the jokes, draws the characters badly on
purpose, and records the voice lines; the pipeline does everything
mechanical. **Never add voice synthesis or joke generation** — the human
voice and the human writing are the entire strategy; the crude visuals
are the proof of them.

Full user-facing docs are in `README.md`. This file is orientation and
the things a fresh session needs to know that the README doesn't say.

## Environment

Run `./setup.sh` (or `./setup.sh --whisper` when voice-directed mode or
auto-captions are needed). It installs ffmpeg + pillow/numpy/pyyaml/scipy,
regenerates the demo's placeholder assets, and smoke-tests a frame render.
faster-whisper downloads its model from Hugging Face on first use.

## The moving parts

| file | role |
|---|---|
| `pipeline/render.py` | episode yaml -> mp4. Frames via Pillow piped to ffmpeg; audio concatenated per shot and muxed. |
| `pipeline/audiolib.py` | decode, loudness envelope, silence-split of a raw take, syllable peaks, mouth tracks |
| `pipeline/puppet.py` | `split` / `scaffold` / `direct` — one raw phone recording in, per-line wavs or a complete editable episode yaml out |
| `pipeline/director.py` | the voice-direction grammar + staging state machine (docstring = grammar spec) |
| `pipeline/ingest.py` | photo of a marker drawing -> clean transparent PNG (paper removal, line snapping, scipy hole-fill) |
| `pipeline/rig.py` | cutout rigging: rig.json skeleton over one drawing, nearest-bone auto-cut with joint overlap — or a drawn `parts/` kit (two red registration dots per part, left limbs mirrored right, `shape` switching) — FK, stock clips, stock face overlays (blink/mouth stamped in sampled colours); CLI `sheet`/`preview`/`pose` |
| `pipeline/clips/` | stock keyframed clips (walk, run, idle, wave, nod, shake, point, jump, sit, kneel, skip, climb, cartwheel, backflip, aim, aim2, fry) against canonical bone names; show/character `clips/` folders override by name |
| `tools/rig_editor.html` | standalone browser click-to-rig editor -> downloads rig.json (bones + face block) |
| `pipeline/kit.py` | the kit template sheet: `template` prints an A4 with fiducials, red joint dots, ghost guides; `ingest` straightens a photo of the filled sheet off the corner squares and writes the whole character folder (parts, rig.json with pivots+face, assembled body.png). `tools/kit_template.pdf` is the committed print-ready copy — regenerate it after layout changes |
| `demo/` | runnable end-to-end example; all art/audio is generated by `demo/make_demo_assets.py` |
| `fonts/satoshi-var.ttf` | caption font, converted from the portfolio's woff2; Pillow variable-font API sets weight 700 |

Episodes live one-folder-per-show (`<show>/{ep.yaml, characters/,
backgrounds/, vo/}`); a character is a folder of pre-aligned same-size
PNGs (`body.png`, optional `talk.png`/`blink.png`, `char.json` with
`anchor` and director `aliases`).

## Commands that matter

```bash
python3 pipeline/render.py demo/episode.yaml            # full render
python3 pipeline/render.py demo/episode.yaml --draft    # half-res, fast
python3 pipeline/render.py demo/episode.yaml --shot 2   # one shot
python3 pipeline/render.py demo/episode.yaml --still 4.2 f.png
python3 pipeline/puppet.py split take.m4a /tmp/lines    # inspect a take
python3 pipeline/puppet.py scaffold take.m4a ep.yaml --char X --bg Y
python3 pipeline/puppet.py direct take.m4a ep.yaml      # voice-directed
python3 pipeline/ingest.py photo.jpg characters/x/body.png [--no-crop]
```

## The script is authoritative (P0, enforced)

When an episode has a `script:` key, `render.py` runs a preflight that
BLOCKS rendering if any dialogue beat is unclaimed, claimed twice, out
of order, silent, or if any shot carries a hand-written caption
(mode `strict`/`director`). Captions are filled from the beat's verbatim
text. Workflow:

```bash
python3 pipeline/screenplay.py parse myshow/script.pdf -o myshow/beats.json
python3 pipeline/screenplay.py vo myshow/beats.json myshow/vo   # placeholders
python3 pipeline/screenplay.py preflight myshow/ep.yaml         # standalone
```

Shots claim beats (`beat: d07`); action beats claimed too = "staged",
otherwise reported as approximated. Characters without assets are
ERRORS unless the episode's `cast:` map explicitly says `silhouette`
(grey stand-in) or `omit`. NEVER abridge, paraphrase, reorder, merge or
soften dialogue; never turn stage directions into on-screen text;
parentheticals like (annoyed) pick performance, not captions.
`steven/ep01.yaml` is the reference implementation (26/26 lines).
See ROADMAP.md for the full production-review priorities (P1–P4).

## Sprite scale is semantic

`world_height` in char.json (1.0 = standing adult; dog 0.35) plus
`defaults.human_height` (0.42 of frame) size sprites via their VISIBLE
bounds — drawing resolution and canvas padding cannot distort scale.
Per-actor `size:` multiplies it (an authored decision). Legacy `scale:`
(canvas-fraction) still works and is what close-up framing uses until
the camera layer (P1) exists.

## Design decisions a future session should not undo

- **12fps, boil jitter, two-frame mouths are the look**, not a quality
  ceiling. Do not smooth, interpolate, or raise the frame rate.
- Mouth flap is driven by **loudness** (syllable peaks by default), never
  by transcription/phonemes. Transcription (`faster-whisper`, optional)
  is used only for captions and for parsing spoken directions.
- All geometry in episode yaml is **normalised** (positions as canvas
  fractions, scale as character-height/canvas-height) so draft and full
  renders are identical.
- `puppet.py direct` must **degrade gracefully on bad transcripts**:
  fuzzy+phonetic name match, aliases, "line ends in a speech verb hands
  off to the next line", unclaimed dialogue goes to the solo or most
  recently directed character. Test changes against garbled input, not
  just clean input (espeak-ng + faster-whisper makes a good worst-case
  harness — that's how the committed demo was made).
- Generated episode yaml is a **draft the human edits**, not a final
  artifact; keep it ordinary, readable yaml.
- **Rigging is opt-in per character** (a rig.json exists) and engages
  per actor only when clips are in play — explicit `clip:`/`clips:`,
  or a slide with no waddle (auto-walk). Everything else renders on
  the untouched flat path; a rigged actor's `scale:` means the same
  as a flat one's.
- **Clips hold stepped keys** (3-4 poses per cycle) — never add
  interpolation smoothing to the stock library; that would kill the
  look. Clip rotations are degrees clockwise; author for a character
  facing right, flips mirror them automatically. dx/dy are fractions
  of the character's standing height.
- **Drawn sheets beat stock faces**: talk.png/blink.png (and pose
  variants) swap onto the head part; the sampled-colour overlays are
  the fallback so nobody HAS to draw them. Do not invert that order.
- **A `parts/` kit replaces the auto-cut entirely** (all or nothing) —
  never mix cut pixels with kit parts on one character; the shared
  body.png pixels would double up. Kit registration is the two-dot
  similarity transform in `Rig._register`; the dots are a fixed span
  per limb (joint + straight-reach), NOT the shape's own extent, which
  is why a bent arm doesn't stretch to a straight arm's length. Kit
  head variants (`head_talk.png`) fill the same role as full sheets —
  `_rig_frame`'s `head_avail` merges both worlds.
- Auto-cut quality depends on the drawing: ingest's hole-fill makes
  paper enclosed between limb and torso opaque, and it will travel
  with whichever bone claims it. Tim's sheets had those fills cleared
  by hand (2026-09-03); prefer a kit for characters that act.

## State of play (2026-08-30)

Everything above is implemented, tested end-to-end in a fresh clone, and
demonstrated by three committed renders: `demo/episode.mp4` (per-shot
audio files), `demo/episode-take.mp4` (one recording, `take:`/`line:`),
`demo/episode-directed.mp4` (staged entirely from directions spoken in
`demo/vo/directed_take.m4a` — synthetic robot voice, hence the chewed
captions). Aaron posted the directed one to Instagram as-is; the
mistranscribed captions ("just one tip", "i am not treated") landed as
part of the joke, so do not "fix" the committed demo take.

Also landed since: **auto-facing** (char.json `facing: left|right` for
profile drawings; sprites flip toward their walk direction or the
shot's talker; front-on characters never flip — mirrored shirt text),
**alt_pose/alt_period** two-frame gesture cycles (arm waves, bird
wing flaps), and the first **foley layer**: per-shot `sfx:` cues
(file/at/gain/dur/loop) and an episode-level looped `ambience:`, mixed
into the dialogue timeline. Sound files live in `<show>/sfx/` with
provenance in SOURCES.md; note user-supplied recordings are often
quiet — check RMS and set gains accordingly (2.0+ is normal).

Since then: **poses** — a character folder can carry extra variants
(`angry.png`, `angry_talk.png`, ...) selected per shot with
`pose: angry`. First real ingested character is `demo/characters/tim/`
(Aaron's own drawing, four variants); his screen test is
`demo/episode-tim.yaml` → `demo/episode-tim.mp4`, which also shows the
mid-sentence punch-in trick: transcribe the voice line with whisper
word timestamps, cut the audio at the trigger word, one shot per piece.

Since then: **cutout rigging** (2026-09-03). A character folder can
carry a rig.json skeleton over the same single drawing: parts are cut
per bone (nearest-segment, joint-overlap dilation) and posed by
reusable stepped clips — walk cycles are real leg swings now, and any
slide on a rigged character walks automatically (waddle suppresses it
for back-compat). Stock clips: walk/idle/wave/nod/shake; canonical
bones with `_upper`→one-piece fallback. Stock faces: char.json (or
rig.json) `face` eyes/mouth anchors get closed-eye and open-mouth
overlays stamped in colours sampled from the drawing — blink.png and
talk.png are now optional everywhere, rigged or flat, and anchors ride
the head bone through nods. Rigs are made in `tools/rig_editor.html`
(or by a session reading body.png and writing rig.json by eye — verify
with `rig.py sheet`). Tim is the reference rig:
`demo/characters/tim/rig.json`, screen test `demo/episode-rig.yaml` →
`demo/episode-rig.mp4`. Do not re-render the older committed demos —
tim now blinks and walks, so their mp4s would no longer match their
render date.

Same day, after Aaron's review of the first screen test ("half his
torso moved with his arm"): **drawn parts kits**. `characters/<n>/
parts/` holds each part as its own drawing — torso, head (+ variants),
`arm_<shape>`/`leg_<shape>` drawn as the left limb and mirrored — each
registered onto its bone by two red dots (joint + straight-reach, a
fixed span per limb; dots erased on load). Clips can switch shapes
(`"shape": [[0, "straight"], [0.55, "bent"]]` — the walk's knees) and
actors can pin them (`shapes: {arm_l: pocket}`). The README section
"The character kit: what to draw" is the drawing list Aaron asked for.
Doug (`demo/characters/doug/`, generated placeholders) is the
reference kit and the second half of the screen test. `point` joined
the stock clips.

Follow-up, same day: **the printable kit template** (`pipeline/kit.py`,
committed print copy `tools/kit_template.pdf`). One A4: four black
corner fiducials, eleven labelled boxes with red joint dots and
non-photo-blue ghost guides in the canonical proportions (bones/face
constants in kit.py). `kit.py ingest photo.jpg characters/<n>` finds
the fiducials, perspective-corrects onto the canonical sheet, cleans
via `ingest.clean` (refactored out for reuse), scrubs ghosts and any
still-visible printed dots (inpainted from surroundings, never paper —
no white holes inside ink), splits the boxes, writes pivots into
rig.json "parts" (no red-dot detection needed — positions are known),
and assembles body.png by posing the kit at rest. Blank optional boxes
are skipped; blank required boxes are errors. Validated end-to-end
against a simulated photo (doug's parts composited into the template,
perspective-warped onto a table, colour cast, JPEG'd) — keep that bar
for layout changes: regenerate the PDF and re-run the round trip.

Aaron's frame-by-frame review of Sugar's first render fixed five
things at once (2026-09-03, "flamingo legs" round): the walk clip's
bent-leg phase now coincides with the forward swing — a bent shape
held on a backward-rotated leg reads as standing on one leg; kit
ingest binarises alpha inside the draw areas ("scissor cut" — soft
shading and ghost tint bleeding through light digital paint otherwise
become translucent veils over the background); kit ingest measures the
DRAWN torso's width at shoulder height and moves the arm bones to fit
(canonical attach points on a narrower torso leave pocket stubs
floating in air); the stock open-mouth overlay lays a sampled skin
patch down first so a drawn closed mouth can't peek past it; and
char.json `flip_to_walk: true` (kit ingest writes it by default)
mirrors a front-on character toward its slide direction — mirrored
shirt text is the accepted cost, the owner decides. When reviewing
motion, extract actual frames and read the channel values alongside
them; the flamingo was invisible in stills picked at random.

Knees are real (Aaron's call: "just add a knee anchor point"): kit
BONES carry leg_X_upper/leg_X_lower with the knee at 48% of the
hip->ankle span (KNEE_F), the template's straight-leg boxes print a
third knee dot, and the kit loader registers the straight leg onto the
full span then splits it at the knee line with overlap — bent-leg
drawings are ignored on two-piece rigs (the joint replaces them; they
remain the fallback for one-piece rigs, and arms stay one-piece).
Clips drive knees through the _lower channels (kneel folds the shin
under, sit hangs shins, run kicks heels); the auto-fit translates each
leg's upper+lower together. TRAP, learned the hard way: a character's
committed sheet.jpg matches the TEMPLATE LAYOUT IT WAS DRAWN ON —
sugar's is the 11-cell v2 — and re-ingesting it after a layout change
mis-slices every cell. Never re-ingest an old sheet with a newer
layout; edit the character's rig.json/parts directly instead (the knee
upgrade was done that way). And CHECK WORK VISUALLY, HARD: full
frames, several phases per move, a ground line under the feet, zoomed
joints — Aaron has caught flamingo legs, floating pockets, backwards
knees and sunk shins from single glances at renders that "passed".

The movement library (2026-09-03, same session): eleven more stock
clips — run, jump, sit, kneel, skip, climb, cartwheel, backflip, aim,
aim2, fry — plus bone-attached PROPS (actor `props:`: an image pinned
to a bone by a rest-pose point, rotating with it; `imgs`+`period` for
two-frame prop cycles like the skipping rope; ladders are plain image
actors staged behind the character). Placeholder prop art in
demo/props/ from make_demo_assets. Full-body flips go through root
rotation channels; big root dy/rot stays inside the pose canvas pad
(0.3*H) — check clipping when adding acrobatics. Kneel is honest about
its limits: a one-piece leg can't fold, so the clip requests shape
"kneel" (falls back to bent → a crouch) and a drawn leg_kneel.png
upgrades it automatically; the shape fallback chain is want → bent →
straight → default, and NO wanted shape means the rest drawing, never
bent. The reel is demo/episode-moves.yaml → demo/episode-moves.mp4.
When authoring clips, verify with a key-moment grid (every clip at 3-6
phases, ground line drawn) before rendering episodes.

Third round, at Aaron's call: **nothing is mirrored, ever**. The
template grew explicit RIGHT arm and leg boxes (17 cells; all right
boxes optional — an empty one means the LEFT art stands in verbatim),
right-arm ghosts curve toward the body, and the kit loader's last
mirror is gone. Mirroring was the root cause of backward knees and
disagreeing shoes; do not reintroduce it. Pocket arms are aimed into
the torso by rig.json `shape_rot` (computed by kit ingest from the
measured pelvis; the rig applies it whenever that shape is active),
so even a left pocket stub standing in on the right lands correctly.

Second review round (pelvis + dots): the template torso is now "torso
+ hips" — its ghost carries a pelvis wrapping past the hip dot, and
kit ingest tucks the leg bones up behind the drawn torso's bottom edge
and fits their spread to its width (legs draw before the torso, so the
joint hides). Dot scrubbing is colour-agnostic: a dot's position is
known exactly, so anything inside the disc that DIFFERS from the
disc's surrounding colour is the dot — bright red on paper, maroon
under translucent paint, near-black after line-snap all get inpainted
from the surroundings. Never assume a printed dot photographs red.

**Sugar** (`demo/characters/sugar/`) is the first REAL kit character:
Aaron drew all eleven boxes (source: `sheet.jpg` in his folder,
ingested by `kit.py ingest`), screen test `demo/episode-sugar.yaml` →
`demo/episode-sugar.mp4`. Two rules landed with him: a kit pose that
lives only on a head part (`head_angry.png`) is valid for `pose:` on
the rigged path (and needs a clip to render — the error says so), and
a posed face NEVER falls back to the neutral talk/blink head (the
expression would flicker away every flap) — the pose head holds and
the stock overlays provide the mouth flap and blink instead. Drawn
`angry_talk`/`angry_blink` parts still win when they exist.

Discussed but unbuilt: per-character close-up
framing in `char.json` (the directed close-up currently assumes a
humanoid head at `at: [0.5, 1.35], scale: 1.5`); pose changes and
camera punch-ins inside a single shot (both currently done with cuts,
which suits the format anyway); director grammar for poses ("tim
angrily says...") and clips ("tim waves"); torso "infill" behind
big limb swings (dilation covers walk-scale rotation; a 90° arm lift
can reveal the cut edge on characters whose limbs overlap the body).
