The shape of the work

What one owner covers.

Hiring one developer to own a codebase only works if that person genuinely covers all of it. This is the split, and where each part of it has been done for real.

The back end
APIs and data models that survive audits: money as decimal, history that is never updated in place, state machines enforced in code and again in the database, raw SQL in the open rather than behind an ORM. C# and TypeScript, proven in the reference build and a decade of CRM and ERP integration work.
The front end
React and Next.js under strict TypeScript, including the unglamorous screens operators actually live in: dense tables, filters, timelines, honest empty states. Checked by looking at the rendered page, not the markup.
The data
Migration, reconciliation and the forensic work when records have been merged on the wrong key for years. Done means reconciled against a source the client trusts, with the working shown, not "the import finished".
The cloud and the pipeline
Azure as infrastructure-as-code, CI that fails loudly, small cheap tiers first and scaling when measurements say so. Plus the integration plumbing between systems: Zapier, Make and n8n when they are the right tool, real code when they are not.
The breaking of it
Adversarial testing before customers find the gaps: prove the hole by using it, re-test after the fix, and clear the phantoms so nobody chases them for a week. The live shopping platform review above is the worked example.
The requirements
The analyst half, and the reason the rest lands: eleven years of pulling the real requirement out of people who disagree with each other, then being the same person who builds it. No handover, so nothing goes missing in one.
The leverage
AI coding agents run like a delivery team: written specifications, adversarial review runs, and proof against sources the agent does not control. The main page walks through how, and this site is itself the result.
